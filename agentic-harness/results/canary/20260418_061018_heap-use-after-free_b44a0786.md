# Heap-Use-After-Free Exploitability Analysis — `canary` (Bug 2)

## 1. Primitive: What Is Written/Read, Offset, Attacker Control

| Attribute | Detail |
|---|---|
| **Class** | Heap-use-after-free — **READ** of 1 byte from freed heap chunk |
| **Location** | `process_entries()`, `canary.c:75` — `uint8_t tag = entries[i].payload[0];` |
| **Freed at** | `canary.c:61` — `free(e->payload);` inside the error branch of `parse_name()` |
| **Allocated at** | `parse_input()`, `canary.c:138` — `entries[i].payload = malloc(avail);` |
| **Stale pointer** | `e->payload` is freed but **never set to NULL**; `e->valid` is simultaneously and incorrectly set to `1` |
| **Read offset** | Fixed at `+0` — always the first byte of the freed chunk |
| **Attacker control over freed size** | The `length` field (bytes 8–9 in the PoC, little-endian `uint16_t`) directly controls `avail` and therefore `malloc(avail)`. Attacker sets this to any value 0–65535. |
| **Trigger condition** | Entry `type == 1` AND `parse_name()` returns `< 0`. `parse_name` fails when `e->length < 2` **or** `name_len == 0`. The PoC uses `length = 0x0058` (88 bytes) but `payload[0] == 0x00`, making `name_len = 0` → immediate failure. |

**PoC dissection (10 bytes):**
```
43 4e 52 59   → magic "CNRY"
01            → version 1
01            → entry_count = 1
01            → entries[0].type = 1 (name)
01 00         → entries[0].length = 0x0001 (1 byte payload)
00            → payload[0] = 0x00  → name_len=0 → parse_name fails
```
The payload allocation is `malloc(1)` with the 1-byte `\x00` payload copied in, freed at line 61, then the stale pointer is dereferenced at line 75.

## 3. Heap Layout: Victim Allocation, Size Class, Adjacent Objects

### Allocation Sequence (PoC with `length=1`)

```
1. malloc(fsize=10)            → data buffer          [tcache bin ~16]
2. calloc(1, sizeof(Entry)=24) → entries array        [tcache bin ~32]
3. malloc(1)                   → entries[0].payload   [tcache bin ~16]  ← VICTIM
   memcpy(payload, "\x00", 1)
   → parse_name() called → fails (name_len==0)
   → free(entries[0].payload)                          ← FREED, returns to tcache[0]
   → e->valid = 1 (dangling pointer left in e->payload)
   → second loop: payload[0] read from freed chunk     ← UAF READ
```

### Escalation-Relevant Layout

The attacker can tune `length` to place the freed chunk in any tcache/fastbin size class (1–65535 bytes). With a **larger `length`** (e.g., 32, 64, 128 bytes), the freed chunk sits in a well-populated tcache bin. If a **subsequent allocation of the same size** is made by another part of the parser (e.g., `parse_name`'s `malloc(name_len+1)` in a second entry), that allocation **reuses the same chunk**, making the stale `entries[i].payload` pointer alias a live `entry->name` buffer — turning the read primitive into a **cross-object information leak or type confusion**.

## 4. Escalation Path: Primitive → Impact

### Step-by-Step

**Step 1 — Establish UAF READ (as demonstrated)**
- Send a type-1 entry with `name_len = 0x00` in the payload. Payload freed, `e->valid=1`.
- Line 75 reads `entries[i].payload[0]` from freed memory.
- **Impact:** deterministic 1-byte read from freed heap chunk.

**Step 2 — Control freed chunk size → target specific tcache bin**
- Set `entries[i].length = N` for chosen bin (e.g., 64 → tcache[3]).
- Freed chunk lands in `tcache[3]`.

**Step 3 — Reclaim freed chunk with attacker-controlled data**
- Add a **second entry** (type=1) in the same input with a crafted payload where `name_len+1 == N`. `parse_name()` calls `malloc(name_len+1)` → receives the **same chunk** just freed.
- `memcpy(e->name, payload+1, name_len)` fills the chunk with attacker bytes.

**Step 4 — Type confusion / info leak via stale pointer**
- `entries[0].payload` still points to the chunk now owned by `entries[1].name`.
- The second loop prints `tag = entries[0].payload[0]` — this now reads `entries[1].name[0]`, an attacker-written byte. This confirms **write-then-read** cross-object control.

**Step 5 — Upgrade to write primitive (if heap shaping possible)**
- If a heap-groomed chunk reclaimed as a **libc internal structure** (e.g., `FILE`, `tcache_perthread_struct`) could be read back via the stale pointer in a richer context, this becomes an **ASLR defeat → RIP control** chain. In this minimal binary the `printf` output channel is limited, but in any derivative application with richer output paths, the leaked pointer values enable full exploitation.

**Step 6 — Combine with Bug 3 (integer overflow OOB write)**
- With ASLR defeated via the UAF info leak, Bug 3's unchecked `buf[i] = 'A'` write at `canary.c:101` can overwrite heap metadata or a known object at a computed offset → **arbitrary write → code execution**.

## 7. Recommended Fix

### Root Cause (two co-located errors at `canary.c:59–63`)

```c
// canary.c:59–63  — BUGGY
if (parse_name(e) < 0) {
    free(e->payload);      // frees but does NOT null
    e->valid = 1;          // marks entry valid despite error — WRONG
    continue;
}
```

### Fix 1 — Null the pointer immediately after free and do NOT mark valid

```c
// canary.c:59–63  — FIXED
if (parse_name(e) < 0) {
    free(e->payload);
    e->payload = NULL;   // ← prevent dangling pointer
    e->valid = 0;        // ← entry is INVALID; do not process in second pass
    continue;
}
e->valid = 1;            // ← only set valid on success
```

### Fix 2 — Defensive null check in the second pass (defense-in-depth)

The second loop at `canary.c:73–77` already checks `entries[i].payload != NULL`:

```c
// canary.c:73–77 — already has a guard, but it relies on pointer being nulled
if (entries[i].valid && entries[i].payload) {   // NULL check present but useless
    uint8_t tag = entries[i].payload[0];        // if pointer not nulled, UAF here
```

This guard is **ineffective** unless Fix 1 is applied. Both fixes are necessary.

### Fix 3 — Cleanup loop must free `payload` (memory leak)

```c
// canary.c:148–151 — current cleanup only frees name, leaks payload on success
for (int i = 0; i < entry_count; i++) {
    free(entries[i].name);
    free(entries[i].payload);  // ← ADD THIS; safe because payload is nulled after free
}
```
